**Time:** 20–30 minutes · **Focus:** error contracts and wrapping

In Go, errors are returned values rather than exceptions. A service can add context to an error without destroying its identity — which will help our future HTTP handler choose between 400, 404, 409 and 500.

## Three error patterns

~~~go
var ErrJobNotFound = errors.New("job not found")
var ErrInvalidTransition = errors.New("invalid transition")

type ValidationError struct {
    Field  string
    Reason string
}

func (e *ValidationError) Error() string {
    return fmt.Sprintf("%s: %s", e.Field, e.Reason)
}
~~~

Compare two wrapping strategies:

~~~go
wrapped := fmt.Errorf("loading job a1: %w", ErrJobNotFound)
errors.Is(wrapped, ErrJobNotFound) // true

lost := fmt.Errorf("loading job a1: %v", ErrJobNotFound)
errors.Is(lost, ErrJobNotFound)    // false
~~~

Use `errors.Is` to match a sentinel in the error chain and `errors.As` to find a typed error.

## Exercise: start a job

~~~go
type JobManager struct {
    jobs map[string]string
}

func (m *JobManager) Start(id string) error {
    // Empty ID -> *ValidationError
    // Missing ID -> wrapped ErrJobNotFound
    // Non-queued status -> wrapped ErrInvalidTransition
    // Queued -> transition to running and return nil
    return nil
}
~~~

Use initial jobs `a1: queued`, `b2: running` and `c3: completed`.

**Acceptance:** Use table-driven tests for `a1`, `b2`, `c3`, an unknown ID and an empty ID. Check sentinel failures with `errors.Is`, typed validation with `errors.As`, and confirm rejected operations never change state. Run `go test -v ./...`.

**Hint:** `fmt.Errorf("job %s: %w", id, ErrJobNotFound)` preserves the sentinel. To extract a validation error, declare `var v *ValidationError` and call `errors.As(err, &v)`.

**Stretch:** Write `HTTPStatus(err error) int`, mapping validation to 400, missing jobs to 404, invalid transitions to 409 and unknown errors to 500. Use `net/http` status constants.
