**Time:** 25–30 minutes · **Focus:** `net/http`, routing, response writers and `httptest`

We've spent six lessons building the pieces of a job-processing service: JSON decoding, maps, pointers, interfaces and meaningful errors. Today we connect those ideas to an HTTP endpoint — with **no framework and no third-party dependencies**.

If you're coming from Express, you already understand requests, responses and route parameters. The Go-specific lesson is how a few small interfaces make HTTP handlers composable and easy to test.

## 1. The HTTP primitives

Here's how you'd register a route in Express:

~~~ts
app.get("/jobs/:id", (req, res) => {
  res.json({ id: req.params.id, status: "queued" });
});
~~~

The corresponding Go 1.22+ route uses `http.ServeMux`:

~~~go
mux := http.NewServeMux()
mux.HandleFunc("GET /jobs/{id}", func(w http.ResponseWriter, r *http.Request) {
    id := r.PathValue("id")

    w.Header().Set("Content-Type", "application/json")
    _ = json.NewEncoder(w).Encode(map[string]string{
        "id": id,
        "status": "queued",
    })
})
~~~

The syntax carries several ideas:

| Go primitive | What it does | Familiar concept |
| --- | --- | --- |
| `http.NewServeMux()` | Creates a router | Express router |
| `"GET /jobs/{id}"` | Matches HTTP method and URL pattern | `app.get("/jobs/:id")` |
| `*http.Request` | Holds method, path, headers and body | `req` |
| `r.PathValue("id")` | Extracts the matched path variable | `req.params.id` |
| `http.ResponseWriter` | Interface for writing status, headers and body | `res` |
| `json.NewEncoder(w)` | Encodes JSON directly to a writer | `res.json(...)` |

**Why a pointer for the request, but an interface for the response?** Go hands the handler a pointer to a concrete `http.Request`, but only requires that the response destination satisfies the `http.ResponseWriter` contract. In production, that is a network response; in tests, it can be an in-memory recorder.

## 2. The handler should translate, not decide

Our business service should know whether a job exists, not whether an HTTP response should be 404.

Follow one request:

~~~text
GET /jobs/a1
    |
    v
http.ServeMux (matches /jobs/{id})
    |
    v
HTTP handler (reads "a1")
    |
    v
JobService.Find("a1")
    |
    +-- Job found ---------> JSON + HTTP 200
    |
    +-- ErrJobNotFound ----> JSON + HTTP 404
    |
    +-- Other error -------> JSON + HTTP 500
~~~

Remember Day 6: wrapping with `%w` lets the handler use `errors.Is(err, ErrJobNotFound)` without comparing error-message text.

### One order-of-operations trap

~~~go
// Correct: headers, then status, then body.
w.Header().Set("Content-Type", "application/json")
w.WriteHeader(http.StatusCreated)
_, _ = w.Write([]byte(`{"status":"queued"}`))
~~~

Writing the body **before** calling `WriteHeader` implicitly sends status **200 OK**. A later `WriteHeader(201)` is too late. For a successful GET, you may omit `WriteHeader` and let the default 200 apply.

## 3. Your exercise: GET /jobs/{id}

Create a tiny standalone Go module. You can also add this handler to an existing project, but keeping it standalone means you do **not** need to finish the earlier exercises first.

~~~bash
mkdir day07
cd day07
go mod init jobapi
~~~

Create `main.go`. The service implementation is supplied; your task is to complete the HTTP handler. The initial response is deliberately `501 Not Implemented`, so the program compiles before the exercise is finished.

~~~go
package main

import (
    "errors"
    "fmt"
    "net/http"
)

var ErrJobNotFound = errors.New("job not found")

type Job struct {
    ID     string `json:"id"`
    Status string `json:"status"`
}

type JobService struct {
    jobs map[string]Job
}

func NewJobService() *JobService {
    return &JobService{
        jobs: map[string]Job{
            "a1": {ID: "a1", Status: "queued"},
            "b2": {ID: "b2", Status: "running"},
            "c3": {ID: "c3", Status: "completed"},
        },
    }
}

func (s *JobService) Find(id string) (Job, error) {
    job, ok := s.jobs[id]
    if !ok {
        return Job{}, fmt.Errorf("job %s: %w", id, ErrJobNotFound)
    }
    return job, nil
}

func NewHandler(service *JobService) http.Handler {
    mux := http.NewServeMux()

    mux.HandleFunc("GET /jobs/{id}", func(w http.ResponseWriter, r *http.Request) {
        // TODO 1: Extract the path variable with r.PathValue("id").
        // TODO 2: Call service.Find(id).
        // TODO 3: On ErrJobNotFound, respond 404 with JSON:
        //         {"error":"job not found"}
        // TODO 4: Handle any other service error with HTTP 500.
        // TODO 5: On success, respond 200 with the job as JSON.
        // Always set Content-Type: application/json for these responses.
        http.Error(w, "not implemented", http.StatusNotImplemented)
    })

    return mux
}

func main() {
    handler := NewHandler(NewJobService())
    fmt.Println("Listening on http://localhost:8080")

    if err := http.ListenAndServe(":8080", handler); err != nil {
        panic(err)
    }
}
~~~

When you implement the TODOs, add the `encoding/json` import. Return immediately after writing an error response so the handler does not try to write a second response.

### What success looks like

~~~http
GET /jobs/a1
HTTP/1.1 200 OK
Content-Type: application/json

{"id":"a1","status":"queued"}
~~~

~~~http
GET /jobs/x9
HTTP/1.1 404 Not Found
Content-Type: application/json

{"error":"job not found"}
~~~

The router itself rejects unsupported methods such as `POST /jobs/a1` with **405 Method Not Allowed**. One Go routing detail worth remembering: a `GET` pattern also matches `HEAD` requests.

## 4. Test the API with no running server

This is the most useful part of the lesson. Instead of starting a real server, `httptest.NewRequest` makes an in-memory request and `httptest.NewRecorder` captures what your handler writes.

Create `main_test.go`:

~~~go
package main

import (
    "encoding/json"
    "net/http"
    "net/http/httptest"
    "testing"
)

func TestGetJob(t *testing.T) {
    handler := NewHandler(NewJobService())

    cases := []struct {
        name       string
        method     string
        path       string
        wantStatus int
        wantBody   map[string]string
    }{
        {
            name:       "existing job",
            method:     http.MethodGet,
            path:       "/jobs/a1",
            wantStatus: http.StatusOK,
            wantBody:   map[string]string{"id": "a1", "status": "queued"},
        },
        {
            name:       "missing job",
            method:     http.MethodGet,
            path:       "/jobs/x9",
            wantStatus: http.StatusNotFound,
            wantBody:   map[string]string{"error": "job not found"},
        },
        {
            name:       "unsupported method",
            method:     http.MethodPost,
            path:       "/jobs/a1",
            wantStatus: http.StatusMethodNotAllowed,
        },
    }

    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            req := httptest.NewRequest(tc.method, tc.path, nil)
            recorder := httptest.NewRecorder()

            handler.ServeHTTP(recorder, req)

            if recorder.Code != tc.wantStatus {
                t.Fatalf("status: got %d, want %d; body=%q",
                    recorder.Code, tc.wantStatus, recorder.Body.String())
            }

            // ServeMux writes its own text/plain 405 response.
            if tc.wantBody == nil {
                return
            }

            if got := recorder.Header().Get("Content-Type"); got != "application/json" {
                t.Fatalf("Content-Type: got %q, want application/json", got)
            }

            var body map[string]string
            if err := json.Unmarshal(recorder.Body.Bytes(), &body); err != nil {
                t.Fatal(err)
            }
            for key, want := range tc.wantBody {
                if got := body[key]; got != want {
                    t.Errorf("body[%q]: got %q, want %q", key, got, want)
                }
            }
        })
    }
}
~~~

The key line is:

~~~go
handler.ServeHTTP(recorder, req)
~~~

`http.Handler` has only one required method: `ServeHTTP(http.ResponseWriter, *http.Request)`. `ServeMux` implements it, and `ResponseRecorder` implements `ResponseWriter`. This is Day 5's small-interface idea in practice.

The test invokes the handler directly: **no socket, no port, no external HTTP client**.

## 5. Run and verify

Run the tests first — they should initially fail because the placeholder returns 501:

~~~bash
go test -v ./...
~~~

After you implement the handler, all three cases should pass. Then run the server and try real HTTP requests:

~~~bash
go run .
# In a second terminal:
curl -i http://localhost:8080/jobs/a1
curl -i http://localhost:8080/jobs/x9
curl -i -X POST http://localhost:8080/jobs/a1
~~~

**Acceptance criteria:** Existing IDs return 200 with the correct JSON; missing IDs return 404 with `{"error":"job not found"}`; unsupported POST returns 405; your responses have the JSON content type; and `go test -v ./...` passes without a live server.

**Hint:** Read the ID with `r.PathValue("id")`. Use `errors.Is` to detect the wrapped sentinel. Set the content type before writing, and encode values with `json.NewEncoder(w).Encode(...)`. Keep a separate error branch for unexpected failures.

**Optional stretch:** Extract a helper `writeJSON(w http.ResponseWriter, status int, value any) error`. Think about how to encode **before** committing headers so an encoding failure doesn't leave the client with a success status and a partial body.

## 6. Bring it back to Day 1

Our original parser accepts an `io.Reader`:

~~~go
func CountStatuses(r io.Reader) (StatusCounts, error)
~~~

A Go HTTP request body also implements `io.Reader`, so a future endpoint could parse it directly:

~~~go
counts, err := CountStatuses(r.Body)
~~~

That's the architectural payoff: small interfaces keep file parsing, HTTP transport and business logic from being tightly coupled.
